[GHSA-3g3m-2fjr-6pw4](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4) concerns directory traversal continuing after an AbortSignal cancels a glob walk. NFT's calls do not supply an AbortSignal, so this specific cancellation failure is not exercised by the current build. A deterministic fixture nevertheless reproduces seven directory reads after starting the old walk versus one with the fixed version: no child traversal is queued after cancellation.

[GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249) concerns excessive expansion of globstar/parent-directory patterns at `optimizationLevel >= 2`. Glob uses level 2 internally; the lint consumers use the default level. The new tests exercise a small bounded pattern against each actual lint consumer's resolved minimatch: the old version ignores the expansion budget, while the patched version throws the expected RangeError. No large resource-exhaustion payload is used.

## Selection and compatibility

The adapter, ESLint, config-array and typescript-eslint are already at their current published releases. NFT has a compatible 1.11.1 patch update within the adapter's `^1.10.2` range, but still requires glob `^13.0.0`. All three lint consumers still require minimatch 10. Supported parent updates alone therefore cannot remove both affected paths.

Glob 13.0.7 includes the cancellation backport, but retains minimatch 10. Glob 14.0.4 supports minimatch 11 and the patched cancellation behavior together. Minimatch 11 replaces its regex-based matcher internals and removes APIs such as `makeRe` and `AST`; forcing it underneath glob 13 would not be an appropriate compatibility assumption. Glob 14 uses the new matcher API. The lint consumers only use the preserved `minimatch()` / `Minimatch` / `match()` / `pattern` interfaces, including partial matching. None use the removed debugging/regex APIs. Node 24 satisfies the new packages' engine ranges.

Overrides are scoped to NFT's glob and each of the three lint consumers' minimatch dependencies. Glob supplies minimatch 11 through its own supported dependency range. There is no global minimatch override and no new source patch. Only NFT, glob, minimatch, path-scurry (2.0.2 → 3.0.0, required by glob), and the new `@isaacs/nonrecursive-glob-match` dependency change. The earlier deepmerge/esbuild fixes remain intact.

The same six compatibility tests pass against both the old and new installs. They cover:

- Dotfiles, braces, extglobs, negation/flipNegate, Unicode filenames, partial directory matching and Windows path matching through each lint consumer.
- NFT's actual `mark`, `dot`, `nodir` and nested-node_modules ignore options; Linux, macOS and Windows shared-library patterns.
- Real `nodeFileTrace` fixtures with dynamic asset reads, dynamic imports, a native addon and its shared library, excluding nested dependency assets.
- The repository's actual JavaScript, TypeScript and Svelte lint configuration, including generated-directory ignores.

Four security regression cases fail on the old graph and pass on the updated graph. Run `npm run test:dependency-security` for these and the existing merge regressions. The test-only `ARMORIA_TOOLCHAIN_BASELINE` option allows differential checks against an older installed dependency tree.

Remove each scoped override when its parent adopts a supported range containing the patched version; rerun these compatibility, tracing and lint checks when changing those ranges. No outstanding glob/minimatch advisory remains in this graph.
