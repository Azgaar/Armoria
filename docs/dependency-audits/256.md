## Fix and upstream blocker

The registry's current releases remain deepmerge 4.3.1, svelte-i18n 4.0.1 and Svelte's Vite plugin 7.3.1. No supported upstream update fixes either merge path. A small patch preserves deepmerge's existing API, cloning, symbol handling, locale partial merging and plugin array replacement. It rejects `__proto__`, `constructor` and `prototype` keys on both operands before writing to the destination. All shipped merge implementations are patched; regression tests resolve the actual consumers and reject a second lockfile copy.

`postinstall` uses `patch-package --error-on-fail`, so a failed patch cannot silently leave an unguarded install. Install with lifecycle scripts enabled (`npm ci`), including development dependencies needed to build the app. The package pin and patch are temporary; do not delete them merely because an audit suggests downgrading SvelteKit or localization.

The application still uses `svelte-i18n`; replacing every localization import is unnecessary for this bounded mitigation. The `noDiscovery`/explicit include list in `vite.config.ts` is preserved. The test-only browser runtime exposes the existing optimized localization module so tests do not create a second store instance.

## Verification

- `npm run test:dependency-security`: actual consumer resolution, both shipped bundles, source/target poisoning, nested placeholders, array elements, ordinary merge compatibility and esbuild transform.
- `npm run test:localization`: isolated empty optimizer cache, French regional saved locale, English fallback, lazily selected German, real language-menu persistence/reload, interpolation/plurals, partial merging and malformed/denied storage. Same-origin request failures (including stale modules and 504 responses) fail the tests. External requests are blocked.
- Existing service/browser regressions retain fixture-only claims and Discord behavior and cover gallery/editor initialization, uploads, exports and rendering.
- `npm run check` includes strict application and service-worker checks; `npm run build` uses the Vercel adapter with no service credentials.
- `npm run test:production` checks a production worker update, offline editor and saved French translations after reload.

Local results: fresh `npm ci` applied both patches; all 89 service/security tests, 53 browser tests and the production offline regression passed. Strict checks reported 0 errors and the existing 92 accessibility warnings. The credential-free Vercel build and changed-file ESLint/Prettier checks passed. Local browser tests used system Chromium 156; CI installs Puppeteer’s pinned Chromium 153.

Post-merge CI, Vercel and public-deployment verification must use the actual upstream merge commit; local checks do not substitute for that gate. Do not automatically close #256 on PR merge before that verification.
