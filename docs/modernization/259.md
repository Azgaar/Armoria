# Shared and navigation runes migration (#259)

Target: `sveltekit`. This checklist covers the page shell, top-level shared components, reusable inputs and navigation components. Editor and SVG-rendering components remain separate under #260 and #261. Store contracts, localization and application layout remain unchanged.

## Batch 1: shared controls and window handlers

Twelve components use runes mode: the three shared notices/window handlers, three reusable inputs, the navbar and five header controls. CoaSync was already migrated in #254. Typed `$props` replace exported props, `$state` holds notice dismissal, `$derived` handles lock state/translated tips, and children snippets replace the two header slots. Stateless components explicitly opt into runes mode. Existing callers retain their store and callback contracts; the remaining menus are covered by batch 2 below.

DOM handlers use Svelte 5 event attributes. Svelte delegates common events, so programmatic parent listeners should use [`on` from `svelte/events`](https://svelte.dev/docs/svelte/svelte-events) to preserve ordering relative to delegated child handlers. The regression test uses that API to verify nested lock/restore handlers stop propagation. Window listeners remain managed by `<svelte:window>`; the production-only leave-page handler now restores its predecessor on unmount.

Message instances retain their initial content and timeout. The baseline comparison exposed an existing race: an outgoing transition can retain its timer and clear a new message with identical text. The timeout now checks object identity, while retaining teardown cleanup and click dismissal.

`test:navigation` covers responsive menu contents and callbacks across the legacy/runes boundary, saved-option unlock/restore, window shortcuts ignored in form fields, reroll/rollback, swipes, notice dismissal, message replacement and expiry. It runs through `test:browser` in existing CI. Existing suites cover uploads, saved options/denied storage, localization, imports, copied links, exports and edit history; strict application/service-worker checks and the credential-free Vercel build remain required.

## Batch 2: header menus and saved options

All 24 components under `navigation/header/menu/**` now use runes mode. `Other` accepts a children snippet, undo/redo availability uses `$derived`, and stateless action/option menus explicitly opt into runes mode. Language, shield, gradient, damasking and gallery-size lists have stable keys. Store updates, saved preferences, localization, copied links and download formats retain their existing contracts.

The install control keeps the browser event in `$state.raw`, consumes it before calling its one-shot `prompt()` method, and removes both window listeners on unmount. `appinstalled` clears any outstanding offer and announces success. Two regression cases fail on the batch-1 baseline and pass here: an older user choice no longer clears a newer offer, and an unmounted install control no longer reacts to window events or accumulates success listeners after remounts. These checks use synthetic browser events; no app installation is performed.

Navigation regressions also cover shield selection through the menu, undo/redo availability and branch replacement, Back saving the edited gallery entry, persisted gradient/damasking/gallery selections and locks, and upload/information/color actions inside the compact menu. Export coverage invokes the real Save menu in editor and gallery modes, comparing the downloaded JSON with the current shared artwork. The component checklist now has 37 migrated entries (including CoaSync), with 12 remaining.

## Batch 3: page shell, gallery, viewer and animated previews

The four components in this batch use runes mode. The page derives gallery dimensions from the size preference and runs matrix transitions before rendering. Only matrix/size changes trigger those transitions; reads and writes of shared history, selection and shield stores remain outside dependency tracking. Gallery generation fills missing history entries before rendering, retains existing artwork, and uses raw state to preserve the object identities shared with legacy editor/rendering components. Typed `$props` and event attributes replace legacy component props and DOM handlers.

The viewer deliberately captures its initial artwork, retaining seeded loading, display dimensions, edit-link behavior and `noedit`. Animated About artwork retains its mount-time design, viewport sizing and transition delay, while palette changes remain reactive. Font/custom-charge loading, URL validation, localization and shared store contracts are unchanged.

`test:gallery` runs through `test:browser` and covers gallery expansion/shrinking without regenerating existing entries, single-card and whole-gallery rerolls/rollback, nonfirst-card editor/history alignment, one-shot seeded initialization, viewer snapshots/edit links/`noedit`, and animated About sizing/palette updates/remounts. These seven cases also pass on the unchanged batch-2 baseline. Existing suites retain malformed URL/import recovery, saved-resource initialization, copied links, downloads, FMG updates and offline coverage. The checklist now has **41 of 49 components migrated, with 8 remaining**.

## Batch 4: upload, custom-resource and information dialogs

The remaining eight components now use runes mode: UploadJSON, UploadRaster, UploadVector, Fonts, Tinctures, About, License and LicenseList. Upload placeholders accept typed children snippets with the dragging state, license selection uses `$bindable`, dialog inputs use local `$state`, and DOM event attributes preserve drag/drop and form default prevention. Vector markup remains sanitized; transform controls track the six matrix values without making direct markup edits overwrite their own transform. Tincture lists derive from the shared store, and persistence effects preserve unlocked defaults on mount and after Restore.

File reads now belong to their dialog's lifetime: close/unmount, Cancel and replacement selections discard pending work. Web fonts capture their submitted name/URL and ignore superseded, closed or unmounted completions and errors. Six lifecycle regression cases fail on the unchanged batch-3 baseline and pass here. Three compatibility cases also pass on that baseline: raster geometry/license persistence, local-font validation/save/restore, and tincture validation/save/remove/restore. These nine cases run through `test:resource-dialogs` in browser CI; existing suites continue to exercise import atomicity, SVG sanitization, markup/transforms, attribution safety, dialog navigation and localization.

All **49 of 49 scoped components** are migrated in this tree, with none deliberately retained in legacy mode. Close #259 only after the final batch is merged and the exact upstream CI/Vercel result and public deployment are verified. Editor and SVG-rendering migrations remain separate under #260 and #261.
