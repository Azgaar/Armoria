## Batch 1: bound controls and layer actions

Thirteen components now use runes mode: Switch, General/Inscription inputs, Stroke/Striped options, Above/Layered/Outside/Divided controls, field Type/Size selectors, layer Controls and Restore. Typed `$props` and `$bindable` declarations retain the existing parent bindings. Layer actions use event attributes and still stop propagation. Their array props are generic, removing the previous `any` declarations.

The parent editor still owns plain legacy objects. Inscription and stroke inputs therefore use [function bindings](https://svelte.dev/docs/svelte/bind) to replace their bound object when a field changes, notifying the parent without depending on deep proxies. A direct nested-binding conversion produced runtime non-reactive-binding warnings; the explicit setters remove those warnings without suppressions or changes to the parent state model.

`test:editor-controls` runs in browser CI. Nine cases verify one undo step per action, unchanged history length during undo/redo, name/zoom/Restore and reload, inscription text/font/style controls, stroke/stacking/division options, stripe-mode defaults, charge layering/outside placement, field type/pattern size, and clone/reorder/remove for ordinary, charge and inscription layers without toggling the parent section. The same tests pass on the unchanged pre-batch baseline. Existing suites retain JSON imports, shared/copy links, FMG race/cancellation, SVG/PNG/JPEG downloads and metadata, saved resources, and production/offline coverage.

For before/after rendering evidence, run the focused suite with `EDITOR_CONTROLS_RESULTS=/tmp/editor-controls.json`. It captures metadata, exported SVG and a rasterized PNG for six edited artworks. This batch matches the baseline's metadata and PNG bytes exactly; exported SVGs also match after normalizing only the random instance numbers in shield/division/inscription IDs and their references. All other SVG content remains unchanged.
